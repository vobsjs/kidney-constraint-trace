# Gentamicin creatinine-clearance PK benchmark

A bounded, metric-driven parameter-fitting benchmark for a **simple
one-compartment pharmacokinetic model whose total clearance is a linear function
of creatinine clearance**. The objective is to find the parameter values that make
the simulated concentration-time curve best fit a literature-derived reference
data set.

This repository is the search space for a `dsh-autoresearch` run: the Host
measures a scalar, a candidate may edit exactly one file, and only strict
improvements are kept.

---

## 1. The model

Structural form, as published by Duong et al. 2022 (Bos et al. 2019 structural
model, re-estimated):

```
CL(CrCl) = CL92 * (1 + SLOPE * (CrCl - 92))        [L/h;  CrCl in mL/min]
k        = CL(CrCl) / V                            [1/h]
```

For a single constant-rate intravenous infusion of dose `D` over `T` hours
(rate `R = D / T`):

```
t <= T :   C(t) = (R / CL) * (1 - exp(-k * t))
t >  T :   C(t) = (R / CL) * (1 - exp(-k * T)) * exp(-k * (t - T))
```

**Tunable parameters** (`model/params.json`, the only mutable path):

| Parameter | Meaning | Unit |
| --- | --- | --- |
| `clearanceAtCrcl92LPerH` | Total clearance at CrCl = 92 mL/min | L/h |
| `crclSlopePerMlMin` | Fractional increase in clearance per mL/min of CrCl | 1/(mL/min) |
| `volumeOfDistributionL` | Apparent volume of distribution | L |

`CrCl = 92 mL/min` is the model's published centring value: the combined-cohort
mean creatinine clearance of the development data set.

## 2. The reference data

`data/reference_points.csv` holds **36 concentration-time reference points**:
six creatinine-clearance strata (45, 60, 75, 92, 110, 130 mL/min) spanning the
development cohort's renal-function range (92.2 ± 48.9 mL/min), each sampled at
0.5, 1, 2, 4, 8 and 12 h within a 24 h dosing interval, after a 400 mg (5 mg/kg ×
80 kg) intravenous infusion over 0.5 h.

### Provenance — please read

These reference points are **model-derived, not raw patient observations**. Each
value is an exact, deterministic evaluation of the published model at the
published cohort descriptors. **No residual noise has been added and no
observations have been simulated.**

Because the fit target is generated by the same structural model the candidate
fits, the correct optimum is *exact parameter recovery*, and the validity check is
agreement between the optimised parameters and the published estimates:

| Parameter | Published value | Source |
| --- | --- | --- |
| `clearanceAtCrcl92LPerH` | **3.44 L/h** | Duong 2022, Table S2 (Bos row) |
| `crclSlopePerMlMin` | **0.00925** | Duong 2022, Table S2 (Bos row) |
| `volumeOfDistributionL` | **22.4 L** | Duong 2022, Table S2 (Bos row) |

Evaluating the published parameters against this reference table gives
RMSE = 3.12 × 10⁻⁷ mg/L, i.e. zero up to the six-decimal rounding of the CSV.
**This is a parameter-recovery benchmark, not an external-validation exercise.**
`data/dataset.json` restates the same provenance in machine-readable form, and
`tools/generate_reference_data.mjs` regenerates the CSV byte-for-byte.

### Why this source, and what was ruled out

A search for an open, digitised **per-patient** concentration-time dataset carrying
creatinine clearance did not find one. The candidate repositories
(`nlmixr2data`, `nlmixr2lib`) hold published parameter sets and simulated cohorts,
not raw observations. The sources examined and rejected:

| Source | Why not used |
| --- | --- |
| Veinstein 2013, *AAC* 57(2):977-982, [doi:10.1128/AAC.01762-12](https://doi.org/10.1128/AAC.01762-12) | Real, openly tabulated per-patient data (Table 3), and it **was** retrieved and verified here. Rejected as the *fit* target because the cohort is anuric/near-anuric on haemodialysis, so renal clearance is ~0 and the CrCl *proportionality* is unidentifiable. Additionally, only its `Cmax` at 1 h is a measured value; `C24`/`C48` are predictions of the same one-compartment model, so fitting them would be partly circular. Retained instead as an **external check** (below and `data/external_validation_veinstein2013.csv`). |
| Storgaard 2026, *Kidney Int Rep*, [doi:10.1016/j.ekir.2026.107020](https://doi.org/10.1016/j.ekir.2026.107020) | Genuine wide renal-function spread (mGFR 13-109 mL/min) with 460 observations, but the individual concentration-time points appear **only in a figure**, not a table. Not digitised here: reading values off a semilog plot with overlapping colour groups would inject unquantified error, and presenting them as exact would misrepresent them. |
| Staatz 2005; Rodvold 1988; Zaske 1982; Sawchuk & Zaske 1976 | Population-level clearance summaries or ranges only; no per-patient concentration-time numbers retrievable from open sources. |

### External consistency check (not part of the metric)

The reference model carries an implicit **non-renal clearance**: extrapolating the
published relation to CrCl = 0 gives

```
CL(0) = 3.44 * (1 + 0.00925 * (0 - 92)) = 0.513 L/h = 8.5 mL/min
```

Veinstein 2013 independently measured exactly this quantity in a completely
different population — anuric critically ill patients on intermittent
haemodialysis — and reported a population estimate of
**CL_NHD = 0.1205 mL/min/kg** (Table 4, RSE 16%). At that study's mean actual body
weight of 75.6 kg this is **9.1 mL/min**.

**Independent agreement within ~7%.** Since Veinstein's cohort may retain minimal
residual renal function, its CL_NHD is an upper bound on true non-renal clearance,
so the agreement is at least this close. Because these patients were anuric they
cannot constrain the CrCl *slope*; what they corroborate is the **non-renal
intercept**, which is the part of the model that a CrCl-only regression would
otherwise leave unconstrained.

For completeness, the same study's volume estimate (V = 0.201 L/kg, Table 4;
0.209 ± 0.060 L/kg per-patient) corresponds to 0.25-0.28 L/kg at the Duong 2022
cohort mean weight of 80 kg. The reference model's V = 22.4 L is 0.28 L/kg, at the
upper end of that band — consistent, given Duong 2022 is a general ICU cohort and
the structural model carries no weight covariate on V.

The per-patient values behind these checks were retrieved from the open PMC full
text and are stored verbatim in `data/external_validation_veinstein2013.csv`.
Transcription was verified by recomputing the paper's own summary row: eight of
nine columns reproduce it exactly. The exception is `CL_HD`, where the ten printed
per-patient values give 74.72 ± 23.57 mL/min but the printed summary row reads
**76.5 ± 23.1** — an inconsistency in the source, not a transcription error (the
published summary string was confirmed in the raw HTML). `CL_HD` is therefore not
used by any check here; the non-renal comparison rests on the Table 4 population
estimate, which is independent of that row.

Neither check feeds the metric or moves the optimum; they are reported so that the
recovered parameters can be judged against evidence the fit never saw.

## 3. The metric

`evaluator/judge.mjs` computes a single scalar:

```
rmse_mg_l = sqrt( mean( (C_predicted(t) - C_reference(t))^2 ) )
```

over all 36 points, in mg/L, to be **minimised**.

## 4. Write boundary

| Path | Status |
| --- | --- |
| `model/params.json` | **mutable** — the candidate's only writable path |
| `evaluator/*` | frozen (`evaluatorFiles`) |
| `data/*` | frozen (declared dataset) |
| `tools/*`, `README.md` | outside the mutable globs |

The autoresearch boundary rejects any candidate that touches a path outside
`mutable_globs`, so the model implementation, the reference data and the metric
cannot be moved.

## 5. Running it

The evaluator is registered with the Host as `gentamicin-crcl-fit` (see
`AUTORESEARCH.md`). To measure the metric directly:

```
node evaluator/judge.mjs              # diagnostics plus the final-line metric
node tools/reference_optimizer.mjs    # reference fit; writes results/reference_fit.json
```

### Platform blocker: `dsh-autoresearch` cannot run on Windows

The plugin's `StateLayout` enforces owner-only POSIX permission bits on its state
root and rejects any directory where `(mode & 0o077) !== 0`. On win32, Node reports
**every** directory as `0o666`, and `chmod()` is a no-op, so that condition can
never be satisfied — `StateLayout.open()` throws even for a freshly created empty
temp directory. This is a property of the plugin, not of this repository:

```
platform: win32 | getuid: undefined
open() FAILED -> StateLayoutError: state root must not be accessible by group or other users
```

The registry resolves correctly (the evaluator id is found and the run reaches
state-layout initialisation), so this is the last barrier, and it is not fixable
from the benchmark side. The plugin's safety documentation is Linux-oriented
throughout (crash recovery already "requires Linux `/proc` evidence").

### Reference result

`tools/reference_optimizer.mjs` performs the same minimisation the autoresearch run
would perform, using a deterministic multi-start Nelder-Mead in log-parameter space.

| | RMSE (mg/L) |
| --- | --- |
| Shipped baseline | 5.592262 |
| Optimum (reference fit) | 2.6970e-07 |
| Autoresearch `target` | 1e-04 — **met** |

Fitted against published:

| Parameter | Fitted | Published | Deviation |
| --- | --- | --- | --- |
| `clearanceAtCrcl92LPerH` | 3.43999995 | 3.44 | 0.000002% |
| `crclSlopePerMlMin` | 0.00925000 | 0.00925 | 0.000004% |
| `volumeOfDistributionL` | 22.40000032 | 22.4 | 0.000001% |

Six widely separated initial guesses all converge to this same point, with a
worst-minus-best RMSE of 3.3e-15 — the optimum is unique and the three parameters
are jointly identifiable from this reference curve. The residual 2.7e-07 floor is
the six-decimal rounding of `data/reference_points.csv`, not a fitting limitation.

Full detail, including every restart, is in `results/reference_fit.json`.
