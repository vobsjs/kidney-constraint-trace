# Gentamicin creatinine-clearance PK benchmark

A bounded, metric-driven parameter-fitting benchmark for a **simple
one-compartment pharmacokinetic model whose total clearance is a linear function
of creatinine clearance**. The objective is to find the parameter values that make
the simulated concentration-time curve best fit a literature-derived reference
data set.

This repository is the search space for a `dsh-autoresearch` run: the Host
measures a scalar, a candidate may edit exactly one file, and only strict
improvements are kept.

---

## 1. The model

Structural form, as published by Duong et al. 2022 (Bos et al. 2019 structural
model, re-estimated):

```
CL(CrCl) = CL92 * (1 + SLOPE * (CrCl - 92))        [L/h;  CrCl in mL/min]
k        = CL(CrCl) / V                            [1/h]
```

For a single constant-rate intravenous infusion of dose `D` over `T` hours
(rate `R = D / T`):

```
t <= T :   C(t) = (R / CL) * (1 - exp(-k * t))
t >  T :   C(t) = (R / CL) * (1 - exp(-k * T)) * exp(-k * (t - T))
```

**Tunable parameters** (`model/params.json`, the only mutable path):

| Parameter | Meaning | Unit |
| --- | --- | --- |
| `clearanceAtCrcl92LPerH` | Total clearance at CrCl = 92 mL/min | L/h |
| `crclSlopePerMlMin` | Fractional increase in clearance per mL/min of CrCl | 1/(mL/min) |
| `volumeOfDistributionL` | Apparent volume of distribution | L |

`CrCl = 92 mL/min` is the model's published centring value: the combined-cohort
mean creatinine clearance of the development data set.

## 2. The reference data

`data/reference_points.csv` holds **36 concentration-time reference points**:
six creatinine-clearance strata (45, 60, 75, 92, 110, 130 mL/min) spanning the
development cohort's renal-function range (92.2 ± 48.9 mL/min), each sampled at
0.5, 1, 2, 4, 8 and 12 h within a 24 h dosing interval, after a 400 mg (5 mg/kg ×
80 kg) intravenous infusion over 0.5 h.

### Provenance — please read

These reference points are **model-derived, not raw patient observations**. Each
value is an exact, deterministic evaluation of the published model at the
published cohort descriptors. **No residual noise has been added and no
observations have been simulated.**

Because the fit target is generated by the same structural model the candidate
fits, the correct optimum is *exact parameter recovery*, and the validity check is
agreement between the optimised parameters and the published estimates:

| Parameter | Published value | Source |
| --- | --- | --- |
| `clearanceAtCrcl92LPerH` | **3.44 L/h** | Duong 2022, Table S2 (Bos row) |
| `crclSlopePerMlMin` | **0.00925** | Duong 2022, Table S2 (Bos row) |
| `volumeOfDistributionL` | **22.4 L** | Duong 2022, Table S2 (Bos row) |

Evaluating the published parameters against this reference table gives
RMSE = 3.12 × 10⁻⁷ mg/L, i.e. zero up to the six-decimal rounding of the CSV.
**This is a parameter-recovery benchmark, not an external-validation exercise.**
`data/dataset.json` restates the same provenance in machine-readable form, and
`tools/generate_reference_data.mjs` regenerates the CSV byte-for-byte.

### Why this source, and what was ruled out

A search for an open, digitised **per-patient** concentration-time dataset carrying
creatinine clearance did not find one. The candidate repositories
(`nlmixr2data`, `nlmixr2lib`) hold published parameter sets and simulated cohorts,
not raw observations. The sources examined and rejected:

| Source | Why not used |
| --- | --- |
| Veinstein 2013, *AAC* 57(2):977-982, [doi:10.1128/AAC.01762-12](https://doi.org/10.1128/AAC.01762-12) | Real per-patient data, but the cohort is anuric/near-anuric on haemodialysis, so renal clearance is ~0 and the CrCl *proportionality* is unidentifiable. Its per-patient Table 3 is also **absent from the openly served full text** (only the abstract is retrievable), so its individual values could not be verified and are deliberately not used. |
| Storgaard 2026, *Kidney Int Rep*, [doi:10.1016/j.ekir.2026.107020](https://doi.org/10.1016/j.ekir.2026.107020) | Good renal-function spread, but individual concentration-time points appear only in a figure, not a table. |
| Staatz 2005; Rodvold 1988 | Population-level clearance summaries only; no per-patient concentration-time numbers. |

**External consistency anchor.** The one openly verifiable number from Veinstein
2013 (abstract) is a volume of distribution of **0.21 ± 0.06 L/kg** in critically
ill haemodialysed patients (single 6 mg/kg infusion over 30 min; Cmax 31.8 ± 16.8
mg/L; C24 4.1 ± 2.3 mg/L). At the 80 kg cohort mean the reference model's V = 22.4 L
is 0.28 L/kg, which is higher — as expected, since Duong 2022 is a general ICU
cohort and the structural model carries no weight covariate on V. This is a
plausibility check on the *magnitude* of V only; it is **not** part of the metric and
does not affect the optimum.

## 3. The metric

`evaluator/judge.mjs` computes a single scalar:

```
rmse_mg_l = sqrt( mean( (C_predicted(t) - C_reference(t))^2 ) )
```

over all 36 points, in mg/L, to be **minimised**.

## 4. Write boundary

| Path | Status |
| --- | --- |
| `model/params.json` | **mutable** — the candidate's only writable path |
| `evaluator/*` | frozen (`evaluatorFiles`) |
| `data/*` | frozen (declared dataset) |
| `tools/*`, `README.md` | outside the mutable globs |

The autoresearch boundary rejects any candidate that touches a path outside
`mutable_globs`, so the model implementation, the reference data and the metric
cannot be moved.

## 5. Running it

The evaluator must first be registered with the Host (see `AUTORESEARCH.md`), then:

```
node evaluator/judge.mjs          # prints diagnostics and the metric line
```

Baseline: RMSE = **5.5923 mg/L** with the shipped parameters. Optimum: RMSE ≈ 0 at
the published parameters.
